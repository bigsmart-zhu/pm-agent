三、模块 04.1：原型生成（核心新增）

核心原则：
1. Tab由业务决定：底部Tab数量 = 最少且必要的导航层级
2. 功能全拆分：每个业务功能 = 1个独立HTML页面
3. index.html是总览：按逻辑分组展示所有页面
4. 先问清楚再做：不确定时反问用户，不要瞎猜

执行步骤：

【步骤1：业务理解】
先确认：
- 核心用户是谁？（老人/子女/护工/医生）
- App有几个角色？
- 核心功能是什么？
- 有哪些设备类型？

【步骤2：确定Tab结构】

参考：
- 陪伴机器人（子女端）= 首页 + 我的（2个Tab）
- 健康管理（患者端）= 首页 + 健康 + 服务 + 我的（4个Tab）
- 电商 = 首页 + 分类 + 购物车 + 我的（4个Tab标配）

⚠️ 如果Tab > 4，问：是不是有些应该合并？
⚠️ 如果Tab < 2，问：是不是只需要单页？

【步骤3：生成完整页面清单】

每个功能 = 1个独立页面：
- 语音播报 → voice-broadcast.html
- 用药提醒 → medication.html
- 家庭相册 → album.html

页面数量参考：
- 简单App：6-10页
- 中等App：10-15页
- 复杂App：15-25页

【步骤4：生成HTML】

技术栈：
- Tailwind CSS CDN：https://cdn.tailwindcss.com
- Font Awesome 6：https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.1/css/all.min.css
- 尺寸：iPhone 14（390px宽 × 844px高）
- iOS风格：状态栏 + 圆角卡片 + 底部Tab导航

每个页面要求：
1. 完整可运行（双击即可在浏览器打开）
2. 页面内链接全部正确
3. 底部Tab高亮当前页
4. 有返回上一页的链接
5. 中文内容，无乱码

【步骤5：生成index.html总览页】

按逻辑分组展示所有页面，用iPhone手机框预览（iframe缩放）。

分组示例（陪伴机器人）：
主导航：首页、我的
设备与服务商：服务商、设备切换
设备详情：手表、拐杖
陪伴机器人功能：语音播报、用药提醒、家庭相册、视频监护...
安全与设置：紧急报警、设备管理...

质量检查点：
- Tab数量是否由业务决定（不是4Tab模板）？
- 页面数量是否与功能数量匹配？
- 每个页面是否完整可运行？
- index.html是否按逻辑分组？

四、Cursor vs PM-Agent 原型生成对比

| 维度 | PM-Agent（旧方式）| Cursor式（新方式）|
| Tab数量 | 套4Tab模板 | 由业务场景决定 |
| 页面数量 | 8-10页（偏少）| 功能数量决定（15-25页）|
| 首页结构 | 功能罗列 | 核心价值突出 |
| 功能组织 | 合并到通用模板 | 每个功能独立页面 |
| index.html | 简单预览 | 按逻辑分组总览 |

核心差距：旧方式在动手前没有先问清楚「谁是用户、核心价值是什么」。
