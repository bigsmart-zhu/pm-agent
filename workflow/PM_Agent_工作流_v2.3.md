## 二、路由规则（v2.3 更新）

| 用户说的特征 | 路由到 | Agent的判断逻辑 |
|------------|--------|----------------|
| "我想做一个XX"/"有个想法" | ①需求发现 | 只有模糊想法，连问题都没定义 |
| "分析一下这个竞品"/"帮我看看这个产品" | ②竞品分析 | 需要提取竞品信息，找到差异化机会 |
| "这个产品有什么问题"/"它做得好不好" | ②竞品分析 + ①需求发现 | 先分析竞品，再找到我们的机会 |
| "我们和XX有什么区别" | ②竞品分析 | 对标分析，找到差异化定位 |
| "这个需求值不值得做"/"做还是不做" | ③机会评估 | 问题已定义，需要量化决策 |
| "帮我写PRD"/"出需求文档" | ④PRD撰写 | 需求已确认，需要结构化输出 |
| "帮我设计页面"/"出个原型"/"怎么交互" | ⑤设计方案 | PRD已有或隐含，需要可视化方案 |
| "上线后怎么看效果"/"怎么度量" | ⑥度量追踪 | 功能已上线，需要闭环验证 |
| "效果不好怎么办"/"数据没达标" | ⑦复盘优化 | 需要回溯分析，迭代改进 |
| 不确定/混合型 | 先①，根据结果自动推荐下一步 | 宁可多验证，不可跳过问题定义 |

## 三、模块 ②：竞品分析（新增）

### PM的思考路径

> **为什么需要竞品分析？**
> 因为"差异化"是产品生存的唯一护城河。
> 如果你和别人一样，用户凭什么选你？
> 竞品分析不是为了"抄"，而是为了"找到别人没做好的地方"。

> **怎么分析竞品？**
> 1. 先提取真实信息（用工具，不要拍脑袋）
> 2. 再对比功能重叠度（哪些是标配，哪些是差异化）
> 3. 最后找机会（竞品的缺陷 = 我们的机会）

### Prompt

## 五、模块依赖关系（v2.3）

```
① 需求发现
    ↓
② 竞品分析 ← 可独立使用
    ↓
③ 机会评估
    ↓
④ PRD 撰写 ← 输入：② 竞品分析结果
    ↓
⑤ 设计方案
    ↓
⑥ 度量追踪
    ↓
⑦ 复盘优化
```

**关键变化**：
- 竞品分析可作为独立模块使用（用户只提供竞品链接）
- 竞品分析结果自动输入到 PRD 撰写的 §0.5 章节
- 差异化机会直接影响机会评估的 Build/Kill 决策

## 六、使用示例（v2.3 新增）

### 示例1：只做竞品分析

> **用户输入：** "帮我分析一下这个产品：https://www.axureshop.com/ys/2337936"

**Agent 路由：** ② 竞品分析

**关键输出：**
- 产品定位：AI 智能体创作平台
- 核心功能：对话、广场、创作、个人中心
- 差异化机会：垂直细分、B2B 定制、更低门槛
- 对标建议：学习清晰导航，抓住 B2B 机会

### 示例2：竞品分析 + PRD 生成

> **用户输入：** "我想做一个 AI 设计工具，先分析一下竞品，然后写 PRD"

**Agent 流程：**
1. 路由到 ② 竞品分析
2. 提取竞品信息（使用 MCP 工具）
3. 找到差异化机会
4. 自动进入 ④ PRD 撰写
5. 在 PRD 中新增 §0.5 竞品对标章节

## 七、技术集成

### 7.1 Axure MCP 工具

| 工具名称 | 用途 | 安装路径 |
|---------|------|---------|
| axure-online | 提取公开 Axure 原型 | `~/.openclaw/workspace/axure-mcp-server` |
| axure-local | 提取本地 Axure 文件 | `~/.openclaw/workspace/axure-html-mcp` |

### 7.2 调用方式

```markdown
**方式 A：公开 Axure 链接**
→ 调用 axure-online.axure_fetch(url)
→ 返回：页面内容、文本、交互逻辑

**方式 B：本地 Axure 文件**
→ 调用 axure-local.scan_projects(path)
→ 调用 axure-local.get_summary(project)
→ 返回：项目结构、功能模块、流程图

**方式 C：网页/产品描述**
→ 调用 web_fetch(url)
→ 返回：产品介绍、功能清单
```
